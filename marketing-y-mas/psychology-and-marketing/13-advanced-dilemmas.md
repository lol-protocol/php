## Dilema 1: Growth vs. Sustainability 🚀

### Escenario Real
Startup crece 10%/mes. Pero para seguir:
- Necesitas $2M más en funding
- Investors quieren 50% MoM growth (imposible sin cortes)
- O pivotear a monetización agresiva

```
OPCIÓN A: Presionar (unsustainable)
- Agregar dark patterns
- Aggressive monetization
- Burn users for short-term metrics

OPCIÓN B: Honest growth (slower)
- Sustainable 10%/mes
- Buscar investors alineados con ética
- Eventualmente más rentable

OPCIÓN C: HYBRID
- Negocia con investors: "Probemos 18% con ética"
- Si no aceptan → busca otros
- Si aceptan → prueba rápidamente

DECISIÓN:
Si investors NO aceptan ética,
no son tus investors. Find others.
```

## Dilema 2: First Mover Advantage vs. Doing Right 🏃

### Escenario
Competitors lanzan features usando técnicas cuestionables.
Tú puedes copiar (fast) o hacer bien (slow).

Market leader suele ganar. Pero...

```
CASO 1: Redes sociales
- Friendster (2002) y MySpace (2003) llegaron primero
- Facebook (2004) llegó después
- Facebook ganó

CASO 2: Buscadores
- AltaVista (1995) llegó primero
- Google (1998) fue más limpio y más rápido
- Google ganó

CASO 3: Smartphones
- BlackBerry y Palm llegaron primero
- iPhone (2007) llegó después con otra propuesta
- iPhone ganó

PATRÓN:
Llegar primero no garantiza ganar. En estos casos
ganó quien hizo un producto claramente mejor, no quien
copió más rápido. (Ninguno de estos casos es sobre
ética: muestran que copiar no es la única forma de competir.)

DECISIÓN:
No copies competitors. Hace 10x mejor.
Si no puedes, espera.
```

## Dilema 3: Engagement Metrics vs. User Wellbeing 😰

### Escenario
Puedes aumentar 30% engagement con:
- Infinite scroll
- Addictive notifications
- Variable rewards

Pero users estarían menos felices.

```
DILEMA:
- Investors aman engagement ↑
- Users aman wellbeing ↑
- Ambos son incompatibles aquí

OPCIÓN A: Choose engagement
- Metrics ↑, wellbeing ↓
- Short-term revenue ↑
- Long-term churn ↑

OPCIÓN B: Choose wellbeing
- Metrics stable, wellbeing ↑
- Short-term revenue stable
- Long-term churn ↓

OPCIÓN C: REDEFINE METRIC
- Cambiar engagement de "time spent"
- A "goals achieved"
- "Meaningful interactions"
- "Problems solved"

Si users logran goals:
- Engagement sigue siendo alto
- Pero ahora es genuina
- Wellbeing también ↑

DECISIÓN:
Redefine metric. No es trade-off.
```

## Dilema 4: Data Request from Government 🏛️

### Escenario Complejo
Government solicita datos. No es warrant, es "request".

```
SITUACIONES:
1. "Give us data de political opposition"
   → Authoritarian regime
   
2. "Give us data de all users"
   → Mass surveillance
   
3. "Give us data de specific criminal"
   → Legitimate law enforcement

OPCIÓN A: Comply always
- Government happy
- Users at risk
- Reputation destroyed

OPCIÓN B: Refuse always
- Users safe
- Government fines company
- Company closed

OPCIÓN C: LEGALLY PROPER
- Require warrant (not request)
- Minimize data (only what warrant says)
- Notify user if legal
- Publish transparency report
- Legal fight if overreach

EJEMPLO REAL (2016):
Apple se negó a crear software para desbloquear
el iPhone del tiroteo de San Bernardino
- Lo impugnó en tribunales
- Recibió apoyo público de gran parte de la industria
- No hubo sentencia: el FBI retiró la demanda
  tras desbloquear el teléfono con ayuda de un tercero
- Apple reforzó su posición pública sobre privacidad

DECISIÓN:
Legal + transparent + fight back.
```

## Dilema 5: Vulnerable Population Protection 👶

### Escenario
Kids use your app. But:
- Parents want monitoring
- Kids want privacy
- Regulations unclear

```
TENSION:
Parents: "I need to protect my child"
Kids: "I need some privacy"
YOU: "I need to be compliant"

OPTION A: Maximum parent control
- Parents see everything
- Kids feel trapped
- Kids hate your app
- Churn ↑

OPTION B: Maximum kid privacy
- Kids empowered
- Parents can't protect
- If something bad happens: you're liable
- Legal + ethical nightmare

OPTION C: BALANCED
- Parents can see aggregated data
  ("Screen time: 2h/day", "Topics used: math")
- Not individual messages
- Kids feel respected
- Parents feel informed
- Opt-in conversations
  ("Child encountered inappropriate content")

IMPLEMENTATION:
- Age-appropriate features
- Parental controls (optional)
- Transparent about limits
- Clear safety resources

DECISION:
Balance both. Transparency with both parties.
```

## Dilema 6: Open Source vs. Monetization 💰

### Escenario
You built great tool. Open source it or sell it?

```
OPTION A: Open source (no revenue)
- Community loves
- Competitors improve on it
- They monetize it
- You get nothing
- Eventually close shop

OPTION B: Closed source + expensive
- You make $$$
- Community hates (not accessible)
- Competitors make free alternative
- Community switches
- You lose

OPTION C: HYBRID (Open Core)
- Core is open source (free)
- Premium features paid
- Community contributes
- You monetize extras
- Everyone wins

EXAMPLE:
GitLab:
- Core open source
- Enterprise paid
- Community thriving
- Company successful

DECISION:
Open core model.
```

## Dilema 7: Employee Pressure to Cut Corners 😓

### Escenario
Your team is tired. Feature due tomorrow.
Engineer: "Can we ship without full privacy review?"

```
PRESSURE:
- Deadline is real
- Team is burned out
- One review delays ship
- Everyone frustrated

OPTION A: Skip review (ship fast)
- Feature ships
- Maybe it's fine
- Maybe it has issue
- If issue: reputation damage > time saved

OPTION B: Delay ship (full review)
- Miss deadline
- Team angry
- But safe ship

OPTION C: PARALLEL REVIEW
- Ship to 5% of users
- Run review simultaneously
- Monitor closely
- If OK → expand to 100%
- If issues → rollback

PROCESS CHANGE:
- Don't do reviews at last minute
- Build review into timeline
- "Feature ready" = "feature + review done"

DECISION:
Parallel review. Change process going forward.
```

## Dilema 8: Contractor vs. Trust 🤝

### Escenario
Contractor from country with weak privacy laws
wants access to customer data to "improve service".

```
RISK:
- Country has lax privacy enforcement
- Contractor might not be trustworthy
- But they're good at their job

OPTION A: Trust them
- They get access
- Maybe they're honest
- Maybe they're not
- One breach = your liability

OPTION B: Deny access
- Contractor can't do job well
- You lose quality vendor

OPTION C: LIMITED ACCESS + OVERSIGHT
- Contractor gets access to anonymized data only
- NO personally identifiable data
- Audit logs (track every access)
- Data Processing Agreement (legal contract)
- VPN + encryption + monitoring
- Regular audits

DECISION:
Limited access + legal protection.
Never assume trustworthiness.
```

## Dilema 9: Ethical Competitor Entry 📊

### Escenario
You have ethical product. New competitor enters:
- 10x less ethical
- 30% cheaper
- Growing fast

Your users considering switching.

```
PANIC MODE:
"We need to match their prices!"
"We need their dark patterns!"
"We need to be more aggressive!"

REALITY CHECK:
- Their model may be unsustainable (not guaranteed)
- Even if it is, it could take years to show
- Your users might leave in the meantime

OPTION A: Match them
- You lose your differentiation
- Now you're both unethical
- You lose

OPTION B: Price war (cut prices 30%)
- Unsustainable
- You run out of money
- You lose

OPTION C: DOUBLE DOWN ON ETHICS
- Make ethical even MORE obvious
- "While X cuts corners, we..."
- Show long-term value
- Target users who care (not price-sensitive)
- Educate market on hidden costs of cheap unethical
- Compete on long-term value, not on who crashes first

HIPÓTESIS A MEDIR (no es un dato):
¿Los usuarios que valoran la ética gastan más
y se quedan más tiempo? Medilo en TU producto
(LTV y retención por segmento) antes de apostar a eso.

DECISION:
Double down, and measure whether it's working.
Don't count on the competitor crashing.
```

## Dilema 10: When Pivot Means Abandoning Ethics 🔄

### Escenario
Original product not working. You need pivot.
Pivot requires abandoning ethical stance.

```
EXAMPLE:
- Built privacy-first messaging
- Market wants group features
- Group features require some data collection
- Now conflicted

OPTION A: Keep original stance
- No group features
- Product dies
- Users scattered
- No one benefited

OPTION B: Abandon ethics for pivot
- Add aggressive data collection
- Grow fast
- Lose original users
- Become like competitors
- You're now just another app

OPTION C: ETHICAL PIVOT
- Add group features
- Do it with minimal data
- Be transparent: "Here's what we collect now"
- Give option: private groups (no collection) vs social groups (some data)
- Users choose
- You evolve ethically

DECISION:
Evolve, don't abandon.
Find ethical path forward.
```

## Framework: When Stuck 🧭

```
APPLY THIS TO ANY DILEMMA:

1. Define the REAL conflict
   (Not "ethics vs. money", but be specific)

2. List all stakeholders
   (Users, team, investors, customers, society)

3. What does each want?
   (Often incompatible)

4. Find THIRD option
   (Usually exists if you're creative)

5. Test hypothesis
   (Small pilot, measure impact)

6. Scale or pivot
   (Based on results)

7. Document decision
   (Communicate why)
```
