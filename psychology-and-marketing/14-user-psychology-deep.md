## Introducción

Entender al usuario no es recolectar datos. Es comprender **por qué piensan, sienten y actúan** como lo hacen.

---

## 1. La Mente del Usuario 🎯

### 1.1 Los Tres Cerebros

```
CEREBRO REPTILIANO (Survival/Instinct)
- Reacciona rápido
- Busca seguridad
- Evita peligro
- "¿Es seguro este app?"

CEREBRO LÍMBICO (Emotion)
- Procesa sentimientos
- Crea conexión
- Recuerda experiencias
- "¿Me hace sentir bien?"

CEREBRO NEOCÓRTEX (Logic)
- Razonamiento consciente
- Análisis
- Decisiones complejas
- "¿Tiene sentido esto?"

VERDAD:
Todos tres influyen en cada decisión.
No es lógica pura, no es emoción pura.
Es mezcla.
```

### 1.2 Cómo Toma Decisiones el Usuario

```
PROCESO SIMPLIFICADO:

User entra a tu app:
1. Reptiliano: "¿Es seguro?" (0.5 seg)
   → Si no confía, se va. FIN.
   
2. Límbico: "¿Me gusta?" (5 seg)
   → Si no siente conexión, se va. FIN.
   
3. Neocórtex: "¿Tiene valor?" (30 sec)
   → Si no entiende beneficio, se va. FIN.

Si pasa todos 3:
User se queda. 
Usa. 
Vuelve.

IMPLICACIÓN:
No puedes ignorar ninguno.
Security + Emotion + Value = Producto ganador.
```

## 2. Motivación: Qué Mueve a los Usuarios 💪

### 2.1 Maslow vs Deci & Ryan

```
MASLOW (jerarquía de necesidades):
1. Fisiológicas (comida, sueño)
2. Seguridad (protección, estabilidad)
3. Pertenencia (comunidad, amor)
4. Estima (respeto, reconocimiento)
5. Autorrealización (propósito, crecimiento)

PERO MASLOW NO EXPLICA ENGAGEMENT.

DECI & RYAN (motivación intrínseca):

AUTONOMÍA:
"¿Puedo elegir cómo usar esto?"
Usuarios con autonomía: 80% retention
Usuarios sin: 30% retention

COMPETENCIA:
"¿Siento que mejoro?"
Usuarios que ven progreso: 2x más engagement
Usuarios sin feedback: abandonan

PROPÓSITO:
"¿Por qué importa esto?"
Usuarios con propósito claro: 3x lifetime value
Usuarios sin: transaccional

CONCLUSIÓN:
Si un app ofrece: Autonomía + Competencia + Propósito
→ Engagement genuino
→ Retención alta
→ Zero churn pressure
```

### 2.2 Motivación Intrínseca vs Extrínseca

```
INTRÍNSECA (viene del user):
✅ "Uso porque amo esto"
✅ "Me aporta valor real"
✅ "Quiero seguir"
→ Dura años
→ Resistente a competencia

EXTRÍNSECA (presión externa):
❌ "Uso porque debo"
❌ "Hay notificación"
❌ "Miedo a perder racha"
→ Dura semanas
→ Churn cuando presión se quita

APLICACIÓN:
¿Tu app depende de notificaciones para engagement?
→ Engagement es extrínseco → Frágil

¿Tu app usa autonomía + competencia + propósito?
→ Engagement es intrínseco → Fuerte
```

## 3. Psicología de la Confianza 🤝

### 3.1 Cómo Se Construye la Confianza

```
PRIMER CONTACT (1 segundo):
- Diseño limpio = confianza
- Diseño cluttered = no confianza
- Color psychology matters

SEGUNDO (5 segundos):
- Copy es clara (no ambigua)
- Explica valor sin jerga
- "Qué voy a lograr" visible

TERCERO (30 segundos):
- Me pide datos → ¿POR QUÉ?
- Si no hay razón clara → no confío
- Si hay razón clara → confío

CUARTO (permanente):
- Hace lo que promete
- Transparent sobre cambios
- Tiene soporte real
- Respeta privacidad

VERDAD:
Confianza toma años de consistencia.
Se pierde en segundos con un breach.
Breach = fin.
```

### 3.2 Señales de Confianza

```
SEÑALES POSITIVAS (aumentan confianza):
✅ Logo + brand consistency
✅ Privacy policy accesible
✅ Real support (no chatbot solo)
✅ Usuarios reales en testimonios
✅ Seguridad visible (HTTPS, encryption info)
✅ Datos de la empresa (dirección, equipo)
✅ Términos legibles (no 50 páginas fine print)
✅ Transparencia sobre cambios
✅ Respuesta a feedback

SEÑALES NEGATIVAS (disminuyen confianza):
❌ Copy deceptiva ("Limited time" siempre)
❌ Presión para compartir datos
❌ Cambios sin notificación
❌ Soporte solo via chat
❌ "Ley de la selva" policies
❌ Dark patterns obvios
❌ Precios sorpresa al final
❌ Datos borrosos/vacos
❌ Promises que no cumple

SCORING:
Count positivos vs negativos.
Si positivos > negativos: Trust Score alto
Si negativos > positivos: User duda
```

## 4. Psicología del Comportamiento 🔄

### 4.1 Hábitos vs Addiction

```
HÁBITO SALUDABLE:
- User elige usarlo
- Agrega valor en cada uso
- Puede dejar sin ansiedad
- Crecimiento visible
- Ejemplo: App de fitness, user mejora diario

ADDICTION (compulsivo):
- User se siente atrapado
- Cada uso = más dopamina
- Ansiedad si no usa
- Sin progreso real
- Ejemplo: Infinite scroll, user se siente mal pero no puede parar

DIFERENCIA CLAVE:
¿Usuario se sentiría MEJOR si dejara de usar?
- Sí → Addiction
- No → Hábito genuino

CÓMO MEDIR:
Survey: "Si dejaras este app por 30 días, ¿te sentiría mejor?"
- Sí: Addiction
- No/Igual: Genuino
```

### 4.2 Trigger → Behavior → Reward (BJ Fogg)

```
BEHAVIOR FORMULA:
B = M × T × P

B (Behavior) = acción que quieres
M (Motivation) = ¿por qué la harían?
T (Trigger) = qué les recuerda?
P (Prompt/Ability) = ¿es fácil?

EJEMPLO 1: Dark Pattern
B = Clickear anuncio spam
M = FOMO (fear of missing out)
T = Notificación a las 3 AM
P = Un click

RESULTADO: Mal engagement, churn alto

EJEMPLO 2: Ético
B = Usar app para lograr meta
M = Progreso visible + comunidad
T = Recordatorio matutino (opt-in)
P = 3 clicks para empezar

RESULTADO: Engagement genuino, retención alta

APLICACIÓN:
Rediseña todos tus triggers con:
¿M es legítimo? (sí o no)
¿T es respetuoso? (opt-in or default)
¿P es honesto? (fácil de dejar también)
```

## 5. Psicología del Cambio 🔄

### 5.1 Por Qué Los Usuarios Resisten Cambio

```
CAMBIO QUE HACES EN TU APP:
"Nuevo diseño, mejor UX"

USUARIO VE:
"Perdí mi referencia. Donde está todo. Estoy confused."

REACCIÓN:
- Frustración
- Miedo (¿Qué cambió?)
- Ira (¿Por qué?)
- Churn ("Uso competencia")

VERDAD:
Cambio = cortisol en el cerebro.
Incluso cambio bueno = estrés inicial.

SOLUCIÓN:
1. Comunica ANTES ("Vamos a mejorar X porque...")
2. Gradual rollout (5% → 50% → 100%)
3. Opción de volver ("Preferir versión anterior por 2 semanas")
4. Soporte visible (tutorial, chat, email)
5. Reconoce frustración ("Sabemos es extraño, aquí está cómo...")
```

### 5.2 Change Curve (Kubler-Ross)

```
User descubre cambio:

SHOCK (1-2 horas):
"¿QUÉ? ¿Por qué?"

NEGACIÓN (1-2 días):
"Esto apesta, vuelvo a la vieja versión"

ANGER (2-5 días):
"¿CÓMO SE ATREVIERON?"

BARGAINING (5-10 días):
"Tal vez no es tan malo"

DEPRESSION (1-2 semanas):
"OK, tengo que aprender esto"

ACCEPTANCE (2-4 semanas):
"Ah, es mejor"

APLICACIÓN:
DONT ship and ghost. 
- Anticipate shock (be ready for support)
- Provide rollback (respect negation)
- Explain reasoning (address anger)
- Make easy (help bargaining)
- Celebrate (accelerate acceptance)
```

## 6. Psicología del Abandono 🚪

### 6.1 Por Qué Se Van Los Usuarios

```
RAZÓN #1: No entienden valor (40% de churn)
- App es confuso
- Features no se ven
- Copy no explica beneficio
- Solution: Onboarding más claro

RAZÓN #2: Mejor alternativa (30% de churn)
- Competencia ofrece más
- UX es mejor
- Cuesta menos
- Solution: Diferencial claro

RAZÓN #3: Cambios sin consulta (15% de churn)
- Precios subieron
- Features que usaban, borradas
- Privacidad cambiada
- Solution: Comunicar anticipadamente

RAZÓN #4: Mala experiencia (10% de churn)
- Bug que no se arregla
- Support que no responde
- Feeling de no importar
- Solution: Care genuino

RAZÓN #5: Otro (5% de churn)
- Circunstancia de vida
- Presupuesto
- Cambio de trabajo
- Solution: Aceptar y aprender

IMPLICACIÓN:
Medir RAZÓN de churn, no solo rate.
Si es #1: Mejora onboarding
Si es #2: Mejora diferencial
Si es #3: Mejora comunicación
Si es #4: Mejora calidad
Si es #5: Normal, no angustiarse
```

### 6.2 Exit Interview (Cuando Se Van)

```
MOMENTO CRÍTICO:
User hace click en "Cancelar suscripción"

¿QUÉ HACES?

OPCIÓN A: Dark pattern (bad)
"Are you sure?" repeated 5x
Cancel button is fake
Email confirmación que dice "Are you sure?"

RESULTADO: Algunos cancelan finalmente, odian tu marca

OPCIÓN B: Indiferencia (neutral)
"Okay, adios"
No pregunta nada
No ofrece nada

RESULTADO: Pierdes insight, no entiendes por qué se van

OPCIÓN C: Genuino (good) ✅
"Nos encantaría tu feedback"

"¿Qué nos faltó? (Selecciona una o varias)"
□ Caro
□ No usaba
□ Mejor alternativa
□ Privacy concerns
□ Mala experiencia
□ Otro

"Si quieres, ¿nos dices más?"
[Texto abierto]

"¿Algún día vuelves?"
□ Tal vez en X meses
□ Depende de cambio específico
□ No, busco alternativa

RESULTADO:
- Entiendes por qué se van
- Algunos cambian de opinión
- Los que se van, se van respetados
- Data para mejorar

VALOR:
Cada "churn reason" = hipótesis para mejorar
Arreglar top 3 razones = 20% reducción en churn
```

## 7. Sesgos Cognitivos en Decisión 🧩

### 7.1 Sesgos Que Afectan Tu Producto

```
CONFIRMATION BIAS:
User busca info que confirma lo que cree
→ Design implication: Presenta múltiples perspectivas
→ Ejemplo: Review de producto, no solo positivos

SUNK COST FALLACY:
"Invertí tiempo/dinero, tengo que seguir"
→ Design implication: Célare el cost sunk (no la uses como retention)
→ Ejemplo: No hagas "racha perdida si no usas"

STATUS QUO BIAS:
"Prefiero lo que ya conozco"
→ Design implication: Cambios deben ser claramente mejores
→ Ejemplo: Gradual rollout, no forced change

RECENCY BIAS:
User recuerda última experiencia
→ Design implication: La última interaction importa más que total
→ Ejemplo: Bug en último feature = user duda de todo

AVAILABILITY HEURISTIC:
User piensa que es verdad lo que recuerda fácil
→ Design implication: Primeras impresiones duran
→ Ejemplo: Buggy onboarding = user nunca confía

FOMO (Fear of Missing Out):
"¿Me estoy perdiendo algo?"
→ Design implication: Muestra valor sin crear pánico
→ Ejemplo: "New feature available" vs "Last chance for..."
```

### 7.2 Cómo Usar Esto Éticamente

```
NO HAGAS:
"Limited time: 24 hours" (cuando es falso)
"Only 3 spots left!" (cuando hay 300)
"You won't believe what X said about Y" (clickbait)

SÍ HACES:
"New research shows X is effective" (true info)
"Join 10K+ users who've already..." (real number)
"We heard feedback and built X" (real feature)

DIFERENCIA:
Primero = manipulation via cognitive bias
Segundo = education + value

Uno genera churn y resentimiento
Otro genera trust y loyalty
```

## 8. Psicología de la Comunidad 👥

### 8.1 Por Qué La Comunidad Retiene

```
USER SOLO:
"Uso app para meta X"
Engagement: Funcional
Retention si: X sigue siendo relevante
Churn si: Encuentro alternativa mejor

USER EN COMUNIDAD:
"Uso app para meta X + para conectar con otros"
Engagement: Funcional + Social
Retention si: X sigue siendo relevante OR comunidad me retiene
Churn si: Abandono comunidad también

EFECTO:
Usuarios en comunidad: 4x más likely quedarse
Incluso si feature no es perfecta

IMPLICACIÓN:
Si tu app tiene comunidad:
- Potencia esa comunidad
- Haz easy conectar con otros
- Celebra wins públicamente
- Crea identity ("Somos [tipo] de personas")

CUIDADO:
No fuerces comunidad artificial (feels fake)
Solo habilita si usuarios quieren
```

### 8.2 Sense of Belonging

```
USUARIO SIENTE PERTENENCIA CUANDO:
✅ Otros usan la app (proof of popularity)
✅ Puede ver perfiles de otros (connection)
✅ Puede interactuar (meaning)
✅ Comparte valores (identity)
✅ Contribuye algo (purpose)
✅ Es reconocido (status)

CÓMO CONSTRUIR:
1. Visualiza "Others use this too"
   (Pero privadamente, sin tracking obsesivo)

2. Enable connections
   "Follow this user", "Find people like you"
   (Con control de privacy)

3. Recognition system
   "Badges", "Leaderboards" (optional)
   (Sin hacer toxic comparison)

4. Shared values
   "Why we exist" visible everywhere
   (Not just marketing)

5. Contribution mechanic
   "Share your X", "Contribute X"
   (Make easy, optional, rewarded)

RESULTADO:
Belonging → Longer retention
Belonging → 2x word-of-mouth
Belonging → User becomes advocate
```

## Conclusión: El Usuario Es Humano 💚

```
Recuerda:

1. Usuario tiene tres cerebros (safety, emotion, logic)
2. Motivación intrínseca > extrínseca
3. Confianza toma años, se pierde en segundos
4. Hábitos genuinos duran, addiction es frágil
5. Cambio produce estrés, comunicación lo mitiga
6. Churn tiene razones, escúchalas
7. Sesgos cognitivos existen, úsalos éticamente
8. Comunidad retiene, pero debe ser auténtica

No trates al usuario como data point.
Trata al usuario como humano.
Porque lo es.

Diseña para humanos.
Los números siguen.
```
